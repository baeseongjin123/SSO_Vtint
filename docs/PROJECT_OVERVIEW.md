## 3. 11주차에 팀이 정한 내용

### 3.1 핵심 아이디어
1. **문제**: C++ 객체 앞부분의 vfptr은 쓰기 가능한 힙에 있어, UAF나 힙 오버플로로 덮으면 가짜 vtable을 통해 제어 흐름을 탈취할 수 있다.
2. **기존 한계**: GCC VTV·SafeDispatch는 소스와 재컴파일이 필요하고, VTGuard는 비밀 쿠키 비교라 정보 유출 시 우회된다.
3. **관찰**: 정상 vtable은 읽기 전용 영역, 주입된 가짜 vtable은 반드시 쓰기 가능 메모리에 있다.
4. **해결**: vtable을 읽기 전용 섹션 `vtsec`으로 옮기고 페이지 시작에 ID를 기록, 가상 호출 직전에 (a) 읽기 전용인지(주입 차단) (b) ID가 맞는지(vtable 아닌 읽기 전용 데이터 악용 차단)를 검사.
5. **효과와 한계**: 주입·변조 공격을 막고 성능 부담 2% 미만. 정상 vtable을 가리키게 하는 **vtable 재사용 공격은 완전히 막지 못함**.

### 3.2 구현 방향
- 원논문의 Windows PE 바이너리 재작성 대신, 핵심 아이디어(vtsec 배치, 페이지 ID, 호출 전 두 검사)를 **Linux 컴파일 단계**에서 재현.
- 바이너리 분석 단계(PEParser, BitCover)는 생략.
- SEH 대신 `/proc/self/maps` 기반 검사를 기본으로, SIGSEGV 방식은 비교 실험용.

### 3.3 기능
| 기능 | 내용 |
|---|---|
| 1. 취약 예제 | Base / Derived / Other / Multi(다중 상속) 클래스. 버퍼와 객체를 한 구조체에 두어 오버플로가 항상 vfptr을 덮게 함. 힙 주소 출력으로 정보 유출 가정. 객체 생성은 별도 파일로 분리해 탈가상화 방지 |
| 2. vtable 재배치 | 링커 스크립트로 vtable을 4KB 정렬 섹션 `vtsec`에 모음. 맨 앞 8바이트에 빌드마다 무작위 ID 기록(LIEF). no-PIE + full RELRO로 빌드 |
| 3. 검사 삽입 | LLVM Pass가 `llvm.type.test` 정보로 가상 호출 지점을 찾아 직전에 검사 호출 삽입 (늦어지면 매크로로 대체) |
| 4. 검사 런타임 | vfptr이 쓰기 불가 영역(`/proc/self/maps`)인지 확인 → 4KB 경계로 내린 주소의 8바이트를 ID와 비교. 실패 시 `VTINT DETECTED` + 검사 이름(READONLY/ID) + vfptr 주소 출력, 종료 코드 99. 공격자 함수는 `HIJACKED` 출력 후 종료 코드 66 |

- 도구(11주차 계획): Ubuntu 22.04 / C++17 / clang·LLVM 15 / Python 3 (LIEF) / Docker / GitHub — 실제 구현은 3.5 참고
- 산출물 형태: **명령행 도구** — 입력 파일을 보호 전과 VTint 적용 바이너리에 차례로 넣고 판정(정상 종료 / 제어 흐름 탈취 / 탐지 후 차단)과 근거(실패한 검사 종류, vfptr 주소, 소속 메모리 영역)를 출력.
- 성공 기준: 세 사례가 기대 결과와 일치 / 다중 상속 포함 정상 입력 묶음에서 오탐 0건 / 다른 팀원 Docker 환경에서 재현.

### 3.4 고정 검증 사례 3종 (수정 금지 — 11주차 보고서 원문)

| 구분 | 입력 | 기대 결과 |
|---|---|---|
| 정상 | 오버플로가 없는 버퍼 크기 이하 입력. Base 포인터로 Derived 객체의 가상 함수를 호출 | 보호 전후 모두 DERIVED RUN 출력 후 종료 코드 0. VTINT DETECTED 출력 없음 |
| 위반 | 버퍼를 넘치게 써서 인접 객체의 vfptr 을 힙에 만든 가짜 vtable 주소로 덮는 입력 (vtable 주입) | 보호 전 HIJACKED 출력 후 종료 코드 66. 보호 후 VTINT DETECTED READONLY 와 vfptr 주소 출력 후 종료 코드 99 이며 HIJACKED 출력 없음 |
| 경계 | vfptr 을 공격자 함수 주소가 담긴 const 함수 포인터 배열(.rodata) 주소로 덮는 입력. 읽기 전용이지만 vtable 이 아닌 위치 | 보호 전 HIJACKED 출력 후 종료 코드 66. 보호 후 읽기 전용 검사는 통과하고 VTINT DETECTED ID 와 vfptr 주소 출력 후 종료 코드 99 이며 HIJACKED 출력 없음 |

### 3.5 실제 구현(12주차, `VTint` 브랜치)과 11주차 계획의 차이
보고서의 "계획 변경 시 사유 메모" 항목에 쓸 내용.

| 항목 | 11주차 계획 | 실제 구현 |
|---|---|---|
| 방식 | 컴파일 단계 재현 (링커 스크립트 + LLVM Pass) | **바이너리 재작성** (컴파일된 exe → ELFParser → BitCover → VRewriter). 원논문 구조에 더 가까움 |
| 분석 단계 | PEParser·BitCover 생략 | 셋 다 ELF용으로 구현 (`tools/elfparser.py`, `bitcover.py`, `vrewriter.py`) |
| 컴파일러 | clang / LLVM 15 | g++ `-O0 -no-pie` (BitCover 가 g++ -O0 의 가상 호출 패턴에 맞춰져 있음) |
| vtsec | 4KB 정렬 섹션, 링커 스크립트로 모음 | LIEF 로 추가한 새 LOAD 세그먼트 `0x500000`(R). vtable 을 **복사**하고 생성자의 vtable 주소를 패치 |
| 검사 삽입 | LLVM Pass 가 `vtint_check()` 호출 삽입 | 가상 호출 명령을 `jmp`로 바꿔 트램펄린(`0x600000`, R+X)으로 우회 → 검사 → 복귀 |
| 검사 런타임 | 일반 함수 | libc 없이 raw syscall 만 쓰는 블롭(`runtime/vtint_check.c`)을 바이너리에 주입 |
| 입력 | 입력 파일 | `argv[1]` 모드: `normal` / `inject` / `rodata` |
| 탐지 출력 | 형식 미정 | stderr: `VTINT DETECTED <READONLY\|ID> vfptr=0x... region=[perms]` |
| 예제 클래스 | Base / Derived / Other / Multi | victim 은 Base / Derived 만 (Other/Multi 는 테스트용 프로그램 `tests/progs` 로 보충) |
| 고정 사례 3종 | — | 그대로 유지, 기대 결과와 일치 |
